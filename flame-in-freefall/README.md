# Flame in Freefall

7oaks’ research dashboard for fire safety in microgravity. Buildless HTML, CSS and JavaScript in `dist/`, with a Node server for original research notes and a Gemini assistant using Google Application Default Credentials (ADC).

## Run locally

Node 22 or later is required.

```sh
npm install
npm start
```

Open http://localhost:4173. Use `PORT=4174 npm start` if the default port is occupied. `npm test` runs the local suite without a cloud model call. `npm run test:gemini` makes a live ADC connection check; success depends on credentials, model availability, permissions and quota.

All six pages share the research navigation: Understand, Prevent, Detect, Suppress and Applications. The home page has a searchable investigation finder, editorial relevance ordering, a three-family comparison and CSV reading-list export. PSI links open searches, not verified links to individual runs.

## Editing content

`context/` contains the team's Markdown. The original-note sections have been removed from the pages; the team will rewrite the page explanations directly. The assistant loads allowlisted documents from disk on every question. It does not have arbitrary filesystem access.

After editing notes, refresh the static copy:

```sh
npm run sync:notes
npm test
```

`dist/research-notes-data.js` is generated by `scripts/sync-research-notes.js`. It is retained as a generated source archive but is no longer loaded by the pages. Tests verify that the generated copy matches the source files byte for byte. Do not edit the generated copy by hand. Live readers use `GET /api/research?page=...`; `/api/context/:page` is an alias.

The investigation catalogue in `dist/investigations.js` is curated from the supplied challenge brief and existing notes. It is separate from the team's original prose. Add verified investigation-specific records and provenance before presenting the catalogue as a numerical dataset. The source drafts remain unchanged by the review; corrections should be made by the team and regenerated.

## What the illustrations establish

These are educational diagrams, not a combustion solver. Controls change selected explanations and authored visual effects. Labels, legends and step-by-step readings explain the physical mechanism. Motion can be paused; reduced-motion preferences are respected.

- Understand compares the same liquid-droplet fuel geometry across Earth, still microgravity and ventilated microgravity. Flamelets are a separate solid-fuel illustration.
- Prevent distinguishes equipment cooling, oxygen supply and smoke transport in the same equipment compartment.
- Detect shows a hypothetical smoke path and sensing mechanisms. Its `t = L/u` calculator assumes a connected path and constant speed; it is not an alarm-time prediction. The qualitative fan slider is separate from the calculator's air speed.
- Suppress distinguishes water-mist heat transfer, electric-field-driven gas motion and acoustic oscillation. Ionic and acoustic methods are experimental approaches. FLEX dilution research is explained separately.
- Understand separates visible hot-flame extinction from a possible subsequent cool reaction. Soot counts are authored tracer tokens, not particle measurements or emissions. The piston diagram stays on Applications and is conceptual.

Detector scores combine draft team ratings with user priorities. They do not establish measured performance, fire probability or suitability for a spacecraft. Investigation order is editorial relevance to a research area, with alphabetical ordering within each relevance category. No hazard-severity score is calculated.

## Gemini and ADC

Edit `context/assistant-prompt.md` for the assistant’s main instructions. The backend reads it for every question; no restart is needed after editing that file. Response schemas and allowed-action validation remain in server code.

The backend uses the Google Gen AI SDK with Vertex AI. Credentials stay outside this repository. Configure project, location and model using `.env.example`; the existing project and model defaults are retained in `server/gemini.js`. The health endpoint confirms the server is running, not that authentication has succeeded.

The assistant receives page-specific Markdown and the selected illustration context. Understand includes the current droplet stage, visibility overlay and soot selections; Applications includes the piston stage. Values are validated on the server. The backend reads `context/README.md` on each question to explain relationships between pages. Suggested questions in the assistant fill the input without making a request until submitted. On the home page it receives all 12 source notes. It is instructed to retain accurate source terminology, define unfamiliar terms, cite document IDs, distinguish draft claims from interpretation, and identify missing measurements. Source-ID matching does not verify that a generated claim is supported; review the cited notes.

Actions are allowlisted and validated on the server and in the browser. Page navigation happens automatically when requested, carrying the conversation and pending controls to the destination. Controls include droplet stage, enhanced visibility, soot formation/oxidation, engine stage, research scenes and Detect settings. Scrolling supports named sections on every page. Scene changes use known controls; model-generated code is never executed. Replies to an earlier selection must not override a newer selection.

Detect also supports local commands without a model call: `/go workspace`, `/go methods`, `/go calculations`, `/go comparison`, `/go evidence`, and `/set FIELD VALUE`. For example, `/set method gas` or `/set velocity 0.2`. Settings are versioned and stored locally; storage failures are non-fatal.

The existing process-wide request throttle is a local safeguard, not public authentication or a distributed quota. Production hosting needs access and quota controls. This review does not publish the site or alter cloud IAM.

### Conversation and response display

The shared assistant saves up to 40 messages in browser localStorage (`7oaks:conversation:v1`). The most recent 12 messages, capped at 24,000 characters, are sent with each question. Use **Clear conversation** to remove the local conversation; existing simulation settings are retained. Browser storage failures are handled without breaking chat, but cross-page automatic navigation is skipped if conversation storage is unavailable.

Responses use a character-by-character typewriter effect after the model returns; this is not network token streaming. **Show full answer** skips the effect, and reduced-motion preferences display the full answer immediately. Markdown bold, italic, headings, lists, inline code and code blocks are rendered with DOM elements; raw HTML is never executed.

`assistant-actions.js` is the browser/server action contract. Navigation can be followed by destination controls and scrolling. A short-lived sessionStorage queue is consumed once on the destination page; old conversation actions are never replayed. Responses are stored before navigation. Automatic navigation and control changes are skipped when the user changes the scene while the answer is being prepared.

Gemini action responses use an API-enforced JSON schema (`server/agent-response.js`). The response text and validated actions are processed separately. A legacy reply containing prose followed by one fenced JSON envelope is decoded; malformed or ambiguous envelopes fail explicitly without displaying success claims. Run `npm run test:gemini -- --agent` to check a live scene-change and scroll request through the backend.

Action history now stores the validated command list and its result with each assistant message. Explicit requests such as “can you redo your previous command?” and the **Repeat last action** button replay those commands locally, without asking the model to infer them from prose. Legacy replies that did not record commands require a fresh explicit demonstration request once. Legacy responses apply controls before the typing effect; new walkthroughs alternate explanation and actions as described below. Unchanged legacy values are reported as already selected.

### Guided text and page actions

The assistant now returns ordered `steps`, each containing Markdown `text` followed by up to two actions. Limits are eight steps and eight actions overall. The browser reveals one paragraph, operates the relevant control, allows observation time, then reveals the next paragraph. Numeric sliders move over 1.8 seconds with eased movement; discrete controls select their authored states. Background motion slows during observation, and reduced-motion preferences bypass the transitions.

Edit [the command manual](context/assistant-commands.md) to explain usage and [the main prompt](context/assistant-prompt.md) to change tone. Both are loaded for every agent request. The authoritative page/control/button allowlist lives in `dist/assistant-actions.js`. Changing the manual cannot enable arbitrary buttons, selectors or scripts. Unsupported new plans fail as a whole before execution.

**Stop walkthrough** cancels pending actions. A trusted user change to a page control also cancels the sequence. Navigation carries only the remaining steps, once, with a two-minute expiry. Reloading ordinary saved history never replays commands. Actions and narrative remain saved for follow-ups; the visible text is saved as it is revealed. The typewriter is a local display effect after the model response arrives, not network token streaming.

Run `python3 tests/browser/walkthrough.py` against a server on port 4174 (or set `TEST_BASE_URL`). It requires Python Playwright and Chromium. Add `--live` to submit real Gemini prompts through the chat form using the server's ADC configuration. `npm test` remains the cloud-free regression suite; `npm run test:gemini -- --agent` checks the real structured response contract.

### Hover definitions

All research pages highlight glossary terms with a dotted underline. Hover or focus for one second to open a definition; tap/click opens it immediately. Escape or leaving the term dismisses it. Popups remain open while the pointer is over the definition.

NASA experiment descriptions come from headings and text in `context/experiments/experiments.md`. Run `npm run sync:glossary` after editing it (`npm run sync:notes` also runs this step). The generated file is `dist/experiment-definitions.js`; do not edit it by hand. Draft descriptions are labelled, and experiments without an entry display a missing-description message. Scientific claims in draft descriptions still require review.
